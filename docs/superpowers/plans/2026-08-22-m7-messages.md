# M7 — Messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One message thread per student with Dimitra — student composer + bubbles at `/app/messages`, admin inbox + reply at `/admin/messages`, unread markers in both navs — with the authorization proven by tests, not just rendered.

**Architecture:** All message reads/writes live in one server-only module, `lib/messages.ts`, whose every function takes the *acting user row* and derives the thread from it (students) or checks `role === "admin"` (tutor); the student path never accepts a student id from the client. Pure validation (`trim`, non-empty, ≤ 4000) sits in `lib/messages-rules.ts`. Pages are server components; mutations are server actions that only call `requireStudent()` / `requireAdmin()` and delegate; polling is a tiny client component calling `router.refresh()`. No new tables (the `messages` table shipped in migration 0005), no events.

**Tech Stack:** Next.js 16 App Router (server actions, `router.refresh`), Drizzle, Vitest on the in-memory PGlite seam (`lib/testing/memory-db.ts`), `components/lumen/*` recipes.

**Spec:** `SPEC.md` §15.3 (messages table), §15.4 `/app/messages`, §15.5 `/admin/messages`, §15.6 M7 checklist.

## Global Constraints

- Same as M6's plan (SPEC/DESIGN authority, server-side enforcement, mobile-first at 390px, `isUuid` at the door, tutor timezone for every displayed time, every commit green, push at the end).

### Task 2: Data layer with authorization (DB-backed tests)

**Files:** Create `lib/messages.ts`, `lib/messages.test.ts`.

**Interfaces (all `server-only`; `actor` is the session `User` row):**
- `class MessageAccessError extends Error { reason: "not-student" | "not-admin" | "paused" | "unknown-student" }`
- `studentThread(actor)` → `Message[]` asc — student only, *always* `actor.id`'s thread
- `markThreadReadForStudent(actor)` → sets `read_at` on unread tutor messages in the actor's thread
- `postStudentMessage(actor, formData)` → `{ ok: true } | { ok: false; reason }` — ignores any `studentId` field; paused or non-student actor throws
- `unreadForStudent(studentId)` → number of tutor messages with `read_at IS NULL`
- `adminThreads(actor)` → `ThreadSummary[]` (`{ student, lastMessage, unread }`), latest activity first, students without messages after (by name) — admin only
- `adminThread(actor, studentId)` → `{ student, messages } | null` — admin only; `null` for unknown/malformed id
- `postTutorReply(actor, studentId, formData)` → inserts `sender: "tutor"` **and marks that thread read for the tutor** — admin only
- `unreadForTutor()` → number of student messages with `read_at IS NULL`

- [ ] Tests (fixtures: admin, students A/B active, P paused): A's post lands in A's thread and B's stays empty; **forged `studentId=B` in the FormData still lands in A's thread**; paused P → throws `paused`; admin calling `postStudentMessage` → throws; A calling `adminThreads` / `adminThread(B)` / `postTutorReply(B)` → throws `not-admin`; empty body → `{ ok: false, reason: "empty" }` and nothing inserted; 4001 chars → `too-long`; admin reply to A → tutor message in A's thread, `unreadForStudent(A) === 1`, B unaffected; `markThreadReadForStudent(A)` → 0 and `read_at` set; `unreadForTutor` counts both students' posts and drops A's after the reply; `adminThreads` order + counts; `adminThread` unknown id → `null`.
