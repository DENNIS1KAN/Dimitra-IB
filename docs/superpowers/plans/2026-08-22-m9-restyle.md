# M9 — Restyle to Dimitra's Palette — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-skin every screen to the owner's palette from `design/lumen-dashboard-mockup.html` (blue nav/links/primary, indigo headings + hero, one orange CTA per view with ink text, jade fills / forest text, cream page, white cards, no yellow), swap the icon font for inline SVGs, switch type to Plus Jakarta Sans — with **zero behavior change** (same routes, same gating, all 111 tests untouched).

**Architecture:** Almost everything flows through `app/globals.css` tokens and the `components/lumen/*` recipes, so the restyle is: (1) new token set + component classes, (2) one `Icon` component rendering inline SVG paths by the same names the code already uses, (3) the student shell becomes the mockup's blue nav bar and `/app` becomes the mockup's hero/note/feature/rail composition as ONE responsive layout, (4) the `TopBar` goes (its back link moves into the page), which removes the second header on module pages. Admin inherits the palette through the same tokens.

**Spec:** `SPEC.md` §15.6 M9 (the owner's brief, verbatim); `design/lumen-dashboard-mockup.html` authoritative, `design/extracted/tokens.css` secondary.

## Global Constraints
- Behavior freeze: no change to `lib/*`, `db/*`, actions, routes, or tests.
- Every displayed colour comes from a token in `globals.css`; the only non-palette literal kept is the error red `#c4320a`.
- Mobile-first; every student route and the admin must report `scrollWidth ≤ viewport` at 390 and 1280.
- Green text is Forest `#1e7a4a`, never Jade; orange carries ink `#131211` text, never white; sunbeam `#ffce00` must not appear in any computed style.
